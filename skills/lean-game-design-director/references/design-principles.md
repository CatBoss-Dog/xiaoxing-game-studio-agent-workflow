# Condensed Game Design Principles

This reference distills practical lessons commonly found across game design books, talks, postmortems, and essays. Use it as a compact checklist, not as doctrine.

## Player Experience First

- Design begins with the experience in the player’s head, not the object in the system.
- A feature is only valuable if it changes player attention, emotion, decision, mastery, or memory.
- The player remembers moments more than rules.

## Interesting Choice

- A choice is interesting when options differ in consequence, timing, risk, identity, or emotional cost.
- A choice is weak when one option is obviously correct, when all options are the same price, or when the player lacks feedback.
- Good choices compress theme into action.

## Feedback Loop

- Every action needs readable feedback: immediate result, delayed consequence, or clear uncertainty.
- Players can tolerate punishment if they understand why it happened and what they could try next.
- Feedback should be sensory or situational before it becomes numeric.

## Elegance

- Elegant systems create many situations from few rules.
- Avoid one-off rules unless they create a major memory point.
- Depth is not the number of systems; depth is meaningful interaction between simple systems.

## Constraints Create Design

- Scarcity, cooldown, inventory limits, route pressure, and risk are not annoyances; they are what make choices visible.
- Add constraints to focus a choice, not to create bookkeeping.
- If a constraint only makes the player manage clutter, remove or merge it.

## Theme Through Mechanics

- Theme should be playable. If the theme is survival, mechanics should ask survival questions: keep, share, spend, risk, carry, abandon, trust, rest, fight, flee.
- Do not add lore that never pressures a choice.
- Character story should appear in what the player does with the character.

## Reduce Cognitive Load

- Players can learn more when each piece has a strong identity.
- Fewer currencies, fewer buttons, fewer states, fewer menus.
- Names must carry meaning. Avoid synonyms that split memory: morale/faith/mood should not coexist unless each asks a different question.

## One Strong Hook

- A character hook: a look, object, wound, behavior, or impossible ability cost.
- A skill hook: one action the player can imagine before reading the numbers.
- An event hook: one situation the player can retell.
- A system hook: one recurring player question.

## Prototyping And Slices

- Build the smallest version that proves the feeling.
- Do not implement full breadth before the core loop is felt.
- A first slice should include trigger, choice, result, feedback, and one repeatable validation path.

## Economy And Progression

- Economy is attention management. Each resource should change how the player plans.
- Progression should open new decisions, not just inflate numbers.
- Upgrades are strongest when they change how players approach situations.

## Combat And Skills

- Combat roles should be readable through behavior: who rushes, marks, blocks, heals, lures, interrupts, protects, or collapses.
- Stats support identity; they do not replace it.
- Passive skills work best when they reward recognizable play patterns or expose character personality.

## Narrative Restraint

- Give less information at once.
- Let the player infer from evidence.
- Backstory is strongest when the player has already felt the consequence.
- Mystery should create action, not just questions.

## Approval Test

Before approving a design, ask:

1. What will the player remember?
2. What decision does it create?
3. What existing system can carry it?
4. What can be removed?
5. How will we know in-game that it worked?
