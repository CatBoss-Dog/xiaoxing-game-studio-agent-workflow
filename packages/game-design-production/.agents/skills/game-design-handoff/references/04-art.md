# 美术需求明细

从已确认玩法和现有资产出发，先拆业务模块，再按UI、图标、模型、动画、特效等制作类型分类。音频有独立表，不混成美术图片数量。

使用 [14列通用合同](../assets/templates/art-contract.json)。现有模板优先，先核实际列名、隐藏列、图片锚点、合并、验证、公式、筛选和空白分隔行；列位不能从另一份表照搬。

## 一行写到能制作

写清名称、使用场景、制作类型、数量和单位、动作或视觉描述、参考图用途、必要状态、复用／新制、交付与验收。已有表没有独立列时，将这些信息放入描述和相应登记，避免未经授权全表扩列。

资源ID确认后保持唯一与稳定。名称和资源路径不是同一字段；缺程序命名时留空／待定，不能造出貌似已接入的ID。

动作需求说明起始、关键动作、结束及前后衔接；特效说明出现、持续、停止和层级；UI说明触发和状态。按需求用短句，不把“一两句话”推广成所有任务的固定字数限制。

## 数量与复用

数量区分套、组、个、枚、条；需求条数、动画状态数、文件数、制作新资产数分别记录。共用资源指定唯一负责人和归属，再由其它页面引用；一份资源不因出现三页就报三份新制量。

“参考风格”不等于“可以直接用原资产”。原件复用、改制、重做分别说明，角色造型、UI图与最终模型／绑定也分开验收。

状态必须区分需求已确认、制作、提交、入端、验收。不能把需求表填完标成资源已完成。

## 参考与交付

每张参考图对应明确描述及适用局部；空图、错图、相互矛盾的描述标出，不自动补成已确认设计。工具可出图不代表本次获授权生成所有缺图。

从工作簿整理 [资源目录](05-directory.md) 时仅建立索引，原表问题另外登记。当前任务未授权修原表时，不以整理目录的名义改原件。
