# 修订、知识留存与按需调用

## 当前稿优先

开工核当前用户文件与来源，不按最高版本号推断权威。原件只读，先记录必要指纹，修改另存。新增和修改默认标黄，原有红绿灰语义继续有效；清除旧黄须有当前要求。新建文档不需要全篇标黄。

用户删改、当前稿差异和助手推断分开。能验证“文件变了”不等于知道具体编辑者和原因；不从旧快照恢复用户删除项。改稿前后检查原件未被覆盖。

## 记录够用的来源

使用 [知识条目](../assets/templates/knowledge-entry.json)，记录用户原话、归纳、理由是否已知、范围、状态、来源、替代关系和验证证据。一案数值和特殊表现留在案例范围，参考资料仍是候选。

多会话协作使用 [状态模板](../assets/templates/shared-state.json)：每个会话只写自己的任务、拟写路径、实际产物和阻碍。写前核冲突；他人状态只作为观察，不能替其宣布已采用或完成。公共索引设明确维护者，新增条目先独立保存再汇总。

## 永久规则逐次确认

每次拟新增、修改、删除策划永久规则，或扩大适用范围，使用 [规则提案](../assets/templates/permanent-rule-proposal.md)，展示：

1. 原条款及来源。
2. 拟改条款与差异。
3. 修改原因。
4. 适用范围和例外。
5. 对现有模板、流程、历史稿与未来任务的影响。

取得本次明确确认后，才更新生效规则并保留历史及版本化验证。尚未确认只保存草案。用户要求“记住”“整理”不等于批准今后所有规则改动；已经授权的普通文稿修订继续执行。

## 下次怎么找

用 [需求索引](../assets/templates/requirement-index.json) 按策划、美术、目录、音频四类指向当前来源、规范和条目。接任务先选相关入口，再核现行原件及尚未汇总的新记录，必要时读取原文。

索引有时间，不是实时作者源；存入文件不等于所有旧聊天都已加载。没有后台任务就不声称持续监听、永久记忆或自动同步。用户提出新规则优先按当前指令和确认状态处理，不能用历史摘要覆盖。
