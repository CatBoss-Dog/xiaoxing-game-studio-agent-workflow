# 需求、范围与证据

## 先确定什么

明确交付对象、读者、当前文件、允许修改区域、输出位置、用户期望的完成标准。可从现有上下文核实的不要反复问；会改变产品规则的缺口才提出精确问题。任务只涉及通用方法时不绑定正式项目。

输入使用 [来源登记](../assets/templates/sources.json)；任务边界使用 [项目信息](../assets/templates/project-profile.json)。每个来源记角色（作者源／参考／历史）、定位、读取日期和指纹；来源冲突保持并列，不能悄悄拼成已批准方案。

## 三种工作范围

| 范围 | 典型请求 | 最小检查 |
|---|---|---|
| 局部 | 改一句、补一行、换一张指定图 | 受影响段落／表格／图片及直接引用 |
| 关联 | 改一条机制、字段或完整状态 | 相关章节、配置、美术音频和异常 |
| 完整 | 新案、新模板、全局样式或全流程重做 | 全文、全表、全图和约定交互 |

新的改动扩大影响时再升级范围。以前的检查仅在来源、工具、模板和关联内容未变化时复用；不是每次都重做全部，也不是旧回执永远有效。

## 视频或录屏

按 [视频证据](../assets/templates/video-evidence.json) 记录时间点、画面所见、玩家操作、UI变化、声音和结果。区分：

- **观察**：能直接从画面／声音或明确原文验证。
- **推断**：为了补齐实现作出的解释，说明依据与置信度。
- **未知**：素材未覆盖，列成问题，不冒充正式规则。

先覆盖开始、关键转折、成功、失败、退出／重进；视频没有的分支只写待确认。单张图不能证明完整时序。截图保留来源与时间，生成图标明用途；表现示意不自动决定实现方式。

将事实转成流程后再整理参数和资源，避免先写一套规则再倒推视频。素材观看和索引不等于已经验收其全部内容。
