# 音乐与音效需求

使用 [13列音频合同](../assets/templates/audio-contract.json)，一条需求一行，数据区不合并；不同方案按实际模块分sheet，文字短、可以复制。

13列：序号、模块、程序Event Name、WWISE事件、名称、策划说明、对接程序、状态、备注、图示、视频文件、策划、合入时间。

先核当前策划和视频中的明确事件，保留既有编号间隔。未提供的程序Event、WWISE事件、负责人和排期留空，不因格式看起来完整而编造。

## 描述必须能对接

在“策划说明”中写清：触发条件与时点、停止条件、是否循环、动作同步点、重复触发／并发去重、复用和必要静音。无需逐行长段落，但关键条件不能省。

音乐、环境循环和一次性动作音效分开；同一个文件可用于多个事件，多条需求不等于多份新音频。下一版本的事件注明范围，不能混入当前版本完成量。

图示和视频列用于真实定位；未取得媒体就保持空白。若来源只有视频，声音属于观察还是推断须标清。不要把游戏不可见的后台事件当成视频已证明。

## 实际制作后的验收

需求表交付只证明交接资料已写，不证明已经录制、合成、试听或接入。只有本次任务包含音频制作／集成时，再按项目确认采样率、格式、音量、循环接缝和导入命名。

实际试听／运行要验证触发时点、停止、退出重进、并发与静音，保护用户其它媒体会话。游戏检查默认无声；需要听声音的专项验收按明确授权，仅控制本次测试会话。
