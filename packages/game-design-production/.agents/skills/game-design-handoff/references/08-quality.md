# 验证、交付与真实完成线

## 四层证据

| 层 | 查什么 | 不能用什么替代 |
|---|---|---|
| 结构 | 文件、表头、层级、链接、主键、字段类型 | 文件存在不能替代内容正确 |
| 语义 | 规则、步骤、图表、资源数量、版本范围一致 | 哈希相同不能替代理解与验收 |
| 视觉 | 实际页面／sheet渲染、可读性、裁切和溢出 | 文本提取不能证明排版 |
| 原生与运行 | 编号续接、保存重开、目录引用、表重算；若范围含游戏则真实入口流程 | 构建通过不能证明正常游玩 |

按改动范围选择检查。新文档或全局样式变化检查全文；局部改动检查受影响页面、表格、引用及布局邻域。发现依赖失效后重做相应链，未受影响的有效证据可以保留。

DOCX须使用可用文档工具渲染并查看对应页面；XLSX须查看有代表性的实际sheet和长文本行，必要时重算公式。工具不具备时注明哪层未验证，不能填写通过。正式固定模板有额外门禁时按其执行。

## 跨文件联查

规则ID、字段、资源名、状态、数量、触发条件、延期范围保持一致。目录链接真实可用；未确认输入不会被配表或示意图偷偷固化。检查用户删除内容没有从旧稿回填。

若任务包含可玩交付，实际走用户约定的一键入口、核心操作、结束、退出／恢复和存档；默认无声，仅控制属于本次测试的进程。纯文档任务不启动游戏运行门禁。

## 交付

每案、每轮独立目录，列出当前文件、修改摘要、验证结果、未决项和后续责任。使用 [验收记录](../assets/templates/acceptance.json) 和 [改动记录](../assets/templates/change-record.json)。

状态至少区分草案、已交付、已验证、用户接受，不能自行代用户接受。输出可打开的实际文件链接；不把工具调用记录当作成品。私人输入／工程／账号资料不随公开方法包交付。
