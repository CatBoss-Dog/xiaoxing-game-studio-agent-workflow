# 策划文档

使用 [策划骨架](../assets/templates/design-document.md)，按任务保留适用章节，不为了凑模板扩写无关系统。

## 内容交接

概述先说明玩家做什么、过程怎样、结果是什么。流程步骤按时间纵向写，一步一个动作／判断；并列条件用项目符号，真正从属于父规则的内容才缩进。不要用编号伪造先后关系。

每个关键规则写明入口与前提、触发、允许操作、状态变化、结果、退出与恢复。资源不足、重复点击、退出重进、结果重复发放等边界按实际机制覆盖；没有决定的分支标为待确认，不编造服务器协议。

固定机制、可配置参数和演算示例分开。流程详解及规则章节先说中文业务含义，再就地引用表名、字段及读取依据。概述、UI概览和配置表下不重复堆解释。保留现行作者表的字段、类型、语法及权威关系。

新 UI 写清入口、布局内容、操作反馈、状态、关闭和重进；资源章保留美术及音乐音效必要表格。精简表达可以减字，不能省掉交接必需项。

## Word 表达

有获授权的正式模板时沿用它；没有时采用通用可读版式，并说明不是专用模板的复刻。

使用原生标题与多级编号，标题层级符合内容关系；目录使用 TOC 域，跨节引用使用可更新 REF，引用包含需要识别的标题内容。不要用手打数字冒充自动编号，不用超链接代替所有正文引用。

文字先中文业务说明，再给表／字段名。语义着色：红色少量强调，绿色覆盖完整表名及字段，待定／延期范围灰色；修订黄底独立保留，不能用一种颜色覆盖另一种语义。标题、列表、段间空白与图注保持一致，不把正文硬塞进列表导致续号或大空白。

修改编号或目录后更新相关域。原生编辑能力的验收应实际插入／回车续号、保存重开、目录跳转和引用更新；仅解包检查 XML 不等于完成这些操作。工具缺失则准确记录未验证项。

## 图表

图之前先解释目的，图后给必要注释。整体图、局部图、文中规则和UI状态一致。指定原素材时保留用户要求的关键外形与构图；参考风格和复用原资产是两种不同授权。

文档中的示意图、实际游戏资产、运行截图分别标识。图片不能仅在目录里存在，实际页面须无裁切、无挤压、可读。

默认元信息及修订行为见 Skill 主入口。完成后按 [验证](08-quality.md) 和 [修订](09-revisions.md) 收口。
