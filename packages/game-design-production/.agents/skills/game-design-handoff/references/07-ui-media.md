# UI、参考与媒体表现

先分清任务：审查现有UI、探索视觉方向、按选定图实现、或只换一张文档图。已选定方向时沿用它，局部修订不自动重启整轮设计。

## 界面合同

新界面至少写清入口、触发、信息层级、元素与按钮、操作反馈、加载／默认／不足／成功／失败／关闭／重进等适用状态。先列真实状态，再出图；画面中的数值、按钮和规则与正文一致。

研究具名游戏参考时核对准确游戏名、页面、截图覆盖与来源；看不到内容就记录覆盖不足，不凭名字编造。借鉴结构和表达，与复制生产资产分开。

## 生成与原素材

用户要求新生成图片时，默认使用当前宿主实际提供的内置图片生成；默认每轮四张，当前明确数量优先。四张是整轮总数，不自动变成每平台四张，参考图和拼版不重复计数。此默认不适用于视频，也不把纯整理任务变成出图任务。

外部生成、代工或另一个工作台只在明确要求时使用。缺少工具时提交可审查的图示说明或待生成项，不把提示词当成已生成图片。

编辑用户指定原图前先查看原图，保持要求保真的结构、比例和身份特征。视频截图、生成示意、设计参考和实际运行画面分别标注；“不用过场动画”等实现限制不等于禁止引用视频帧说明过程。

## 图像验收

先验证一张代表性画面或关键状态：构图、关系、资产形态、数值、文案和参考一致，再扩展。用视觉检查发现错误，不靠文件数量凑完成。

交付包含每张图的用途、来源类别、版本和待确认项。效果图完成不等于可交付UI资产、模型、动画或程序实现。
